# vLLM 0.21.0: Patch Gemma4 streaming reasoning fallback

Date: 2026-05-18

## Context
We run Gemma4 (`gemma-4-e4b-it`) behind vLLM with `--reasoning-parser gemma4` and need **streaming** ChatCompletions to emit `delta.reasoning` (so pi-ghosty / TUI can render thinking separately).

With vLLM **0.21.0** (stable), Gemma4 often generates the end marker `<channel|>` (token id 101) **without** generating the start marker `<|channel>` (token id 100) in the *generated token ids*. In streaming mode, vLLM then:

- emits only `delta.content`
- leaks `<channel|>` into content
- never emits `delta.reasoning`

This reproduces the same behavior we previously saw on nightly before applying a fix.

## Fix
Patch the installed vLLM package in the agentmux venv:

- File patched (in-place):
  - `agentmux/.venv-vllm/lib/python3.12/site-packages/vllm/reasoning/gemma4_reasoning_parser.py`

The patch adds a **Gemma4-specific streaming fallback** (validated previously on our vLLM nightly experiment branches):

- If `<|channel>` start token has not been seen in generated token ids, treat deltas as **reasoning** until `<channel|>` is seen.
- When `<channel|>` arrives in a delta, split that delta into:
  - `delta.reasoning` (before the marker)
  - `delta.content` (after the marker)

Also includes streaming prefix stripping for the `"thought\n"` role label.

## Why this is an in-place patch
We want to stay on vLLM 0.21.0 stable for Gemma4 MTP/spec decoding work, but we also need streaming reasoning separation. Upstream behavior is currently not sufficient for our Gemma4 + template behavior.

## Validation signal
After patching, a streaming probe (`stream=true`, `include_reasoning=true`, `return_token_ids=true`) should show:

- `delta.reasoning` present
- final answer in `delta.content`
- no `<channel|>` leak in content

## Risk / follow-up
This is a local patch to site-packages. If vLLM is upgraded/reinstalled, this change will be overwritten.

If this causes future tool-calling or parsing issues, revert by reinstalling vLLM into `.venv-vllm` or restoring this file from the vLLM 0.21.0 wheel.
